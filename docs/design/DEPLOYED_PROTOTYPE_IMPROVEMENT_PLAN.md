# 배포 프로토타입 개선·수정 플랜

작성일: 2026-10-24 KST
기준 서비스: https://parkingzone.vercel.app/
문서 상태: 전체 플랜 실행 승인 / B·D 일부 검증 완료 / A·C·E·F 잔여 작업 진행 중
착수 당시 코드 기준: `main`, `73793ec`

## 1. 이 문서의 역할

이 문서는 배포 이후 개선 작업의 기준이다. 앞선 대화의 플랜과 지도 설정에 관한 최신 결정을 통합했다. 이 범위에서 과거 문서와 충돌하면 이 문서와 사용자의 이후 지시를 우선한다. 과거 문서를 현재 구현 상태로 해석하지 않는다.

이 문서는 처음에는 플랜 작성 산출물이었으며, 이후 사용자의 **전체 플랜 순서대로 시작** 지시로 로컬 구현·검증이 승인되었다. 아래 작업 단위와 완료 기준을 사용한다. 이 실행 승인을 커밋·푸시·운영 배포 또는 실제 거래 승인으로 확대하지 않는다. 실제 확인 결과는 `docs/records/DEPLOYED_IMPROVEMENT_PROGRESS.md`에 기록한다.

진행도는 해당 작업 단위의 완료 기준에 따라 보고한다. UI 몇 군데를 수정했다고 프로젝트 전체·팀 학습·UT 진행률을 올리지 않는다.

## 4. 작업 순서와 선행 조건

| 순서 | 작업 단위 | 산출물·완료 조건 |
|---|---|---|
| A | 원본·배포 상태 대조 | 화면별 진입·조작·복귀·빈 상태·근거 목록. 미관찰 항목 구분 |
| B | 알림·중복 조회·화면 재생성 개선 | 60초 조회 정책, 요청 하나 공유, 조용한 갱신, 상태 유지 검증 |
| C | 15곳 요금 조사·날짜 조건 보강 | 시설별 출처와 요금표, 상품 적용 조건, 미확인·충돌 목록 |
| D | 실제 바텀시트 구현 | 중간/펼침/닫힘, 내부 스크롤, 지도와의 제스처 분리 |

A의 확인된 화면부터 후속 작업을 진행한다. C의 가격 조사 결과 없이 가격을 먼저 입력하지 않는다. 미관찰 화면 하나 때문에 독립적인 B를 중단할 필요는 없지만, 해당 화면은 임의 설계로 채우지 않는다.

### A. 원본과 배포 상태 대조

- 아이폰 미러링의 기존 앱을 우선 사용하고, 저장된 앱 캡처를 보조 근거로 사용한다. 공식 웹은 시설·상품·요금 조사에 사용한다.
- 화면별로 `원본 근거 / 진입 / 조작 / 표시 결과 / 뒤로가기 / 로컬 재현 방식`을 기록한다. 과거 캡처와 현재 앱이 다르면 구분한다.
- 지도·검색·날짜/시간·필터·목록·일반/공유 상세·상품 안내·구매 직전, AI·월주차·세차·내 공유·즐겨찾기·내 이용권을 대조 대상으로 삼는다.
- 미러링에서 접근하지 못한 화면은 사용자 조작이나 기존 자료로 확인한다. 자료가 부족하면 그 부분의 구현을 보류하고 확인 사항을 묶어 질문한다. 마이크 제한을 우회하거나 실제 거래 버튼을 눌러 관찰하지 않는다.

### B. 버벅임과 불필요한 알림 개선

**조회 정책**

- 최초 진입에서는 현황을 한 번 조회한다. 지도·시설 정보·화면 조작은 이 응답을 기다리느라 막지 않는다.
- 마지막 성공 조회 후 60초 이내에는 탭 복귀·자동 조회를 생략한다. 60초 이상이면 기존 화면을 유지하며 뒤에서 조회한다.
- 자동 조회는 보이는 탭에서만 수행한다. 성공·실패 후 다음 요청을 예약하는 방식으로 관리하고, 탭 복귀와 주기 조회가 중복 예약되지 않게 한다.
- 조회 중 새 요청이 발생하면 진행 중인 요청 하나를 공유한다. 수동 갱신은 60초 조건을 건너뛰되 진행 중 요청을 중복 생성하지 않는다.
- 실패 후 자동 재시도는 최소 60초 간격으로 한다. 숨긴 탭에서는 재시도하지 않는다. 네트워크 응답 시간이 0이 된다고 보장하지 않는다.

**알림·실패 처리**

- 자동 조회의 ‘실제 DB 현황 조회 중’, 조회 성공·더미 여부 같은 개발용 토스트를 제거한다. 검색·날짜 선택의 단순 완료 알림도 제거한다.
- 최초 현황 대기 표시는 필요한 정보 영역에만 둔다. 이후 갱신에서는 전체 로딩 화면·덮개·조작 차단을 사용하지 않는다.
- 조회 실패 시 마지막 정상 데이터를 유지하고 해당 영역에 짧은 실패 안내와 재시도를 제공한다. 첫 조회부터 실패했다면 현황 미확인을 표시하되 시설·확인된 요금은 계속 탐색할 수 있게 한다.
- 브라우저 조회 실패를 DB의 `latest_collection` 결과에 덮어쓰지 않는다. 화면의 조회 상태를 별도로 관리해 마지막 조회 기록임을 구분한다.
- 원천 시각 없음·수집 실패·오래된 기록을 정상 현재 상태로 바꾸지 않는다. 기존 20분 최신성 기준과 원천/수집 시각 구분을 유지한다.

**화면·지도 유지**

- 검색어·입력 포커스·선택 상품·지도 중심/배율·시트 높이·목록/상세 스크롤·펼친 안내를 유지한다.
- 변경된 정보만 갱신한다. 시간 경과 확인 때문에 목록과 상세 본문 전체를 다시 만들지 않는다. 숨겨진 화면은 열 때 최신 상태를 반영한다.
- 지도 인스턴스를 유지하고 시설 ID로 표식을 재사용한다. 가격·위치·노출 조건이 바뀌지 않으면 표식을 삭제·재생성하지 않는다.
- 선택한 상품이 새 조건에서 유효하지 않으면 다른 상품으로 몰래 바꾸지 않는다. 해당 상품의 이용 불가를 표시하고 다시 선택하게 한다.

### C. 요금·상품·날짜 조건

**조사와 연결**

- 기존 15곳 각각의 이름·주소를 모두의주차장 시설 페이지와 대조한다. 현장 요금은 시설 운영 주체의 공식 자료도 확인한다.
- 서울시 시설 ID·주소·현황을 기준으로 유지한다. 이미 사용자가 동일 시설로 확인한 메가박스스퀘어·서울숲IT밸리의 상품 연결을 다시 보류하지 않는다. 원문 주소 차이는 보존한다.
- 공식 판매 카드·상품 상세를 AI 요약보다 우선한다. 실제 상품·현장 자료끼리 충돌하면 임의 선택하지 않는다.
- 현장 요금은 기본 시간/금액, 추가 단위/금액, 일 최대요금, 운영시간, 출처·확인 시각을 확인되는 만큼 기록한다. 누락값을 0원으로 채우지 않는다.
- 주차권은 상품 ID·명칭·가격·이용시간·판매 시작/종료·평일/주말/공휴일 조건·유효기간·출처·확인 시각을 관리한다. 원문과 정리한 조건을 구분한다.
- 15곳을 `확인 / 미확인 / 미판매 확인 / 자료 충돌`로 정리한다. 미확인과 미판매는 다르다. 확인하지 못한 시설과 이유를 사용자에게 알린다.

**표시와 유효성**

- ‘현장 요금’과 ‘앱 주차권’을 다른 항목으로 표시한다. 일반 주차장 정보에서는 확인된 요금을 보여주고, ‘오늘 주차권’ 목록에는 해당 날짜·시간 조건에 맞는 확인 상품만 표시한다.
- 앱 주차권이 없는 시설도 지도와 일반 상세에서 접근할 수 있게 한다. 현장 요금으로 가짜 주차권·구매 버튼을 만들지 않는다.
- 상품의 반복 적용 조건은 공식 근거가 확인된 경우만 등록한다. 공휴일을 단순 주말 계산으로 처리하지 않는다. 적용일 근거가 없으면 판매 가능을 단정하지 않는다.
- 한국 시간의 전체 날짜(연·월·일)로 선택·판정한다. 자정·월/연 변경과 다음 달 선택을 지원하고, 갱신 때문에 사용자가 고른 미래 날짜를 오늘로 되돌리지 않는다.
- 가격 자동 수집, 근거가 부족한 예상 주차비 계산, 할인·잔여 판매 수량 추정은 추가하지 않는다. 확인 시각을 보관하고 실제 구매 가격이나 입차를 보장하지 않는다.

### D. 실제 바텀시트

- 현재 모바일 웹 구조를 유지한다. 이 문제만으로 프레임워크 전환·네이티브 앱 재개발을 시작하지 않는다.
- 목록·상세가 공통 시트 동작을 사용하도록 분리한다. 기본 중간 높이는 사용 가능한 화면의 약 50%, 펼침은 약 90%이며 안전 영역을 반영한다. 닫으면 지도 화면으로 돌아간다.
- 헤더·손잡이 드래그와 누르기 모두 지원한다. 손잡이 터치 영역은 최소 44px로 확보한다. 버튼 조작으로도 동일 상태에 접근할 수 있게 한다.
- 본문은 내부 스크롤을 우선한다. 본문 맨 위에서 아래로 당길 때만 시트 접기로 넘기며, 일반 본문 스크롤이 시트를 움직이지 않게 한다.
- 시트 제스처가 지도에 전달되지 않게 하고, 지도·로고·표식은 시트 아래에 둔다. 지도 안에 필요한 출처 표시는 유지한다.
- 구매 버튼은 시트 하단에 고정한다. 아이폰 안전 영역·브라우저 주소창·키보드로 내용이나 버튼이 가려지지 않게 한다.
- 목록→상세→뒤로가기에서 목록 높이·스크롤·선택을 복원한다. 지도와 시트 높이 변화 시 선택 표식이 보이는 영역을 고려한다.

### E. 기존 앱 화면과 조작 재현

- 원본의 구조·명칭·정보 순서·아이콘·이동 흐름을 기준으로 한다. 별도 디자인 개편, 비교 모드, 더미 선택 패널, 진행자용 도구를 추가하지 않는다.
- 추가 메뉴를 누르면 해당 화면으로 이동하게 한다. 매번 ‘테스트 범위가 아닙니다’라는 알림만 띄우는 처리는 없앤다.
- 월주차·공유면·세차는 원본의 탐색 화면·필터·상세 구조를 재현한다. 기존 15곳에서 해당 유형/상품이 확인되지 않으면 적절한 빈 상태를 표시한다. 다른 시설이나 가상 가격을 만들지 않는다.
- AI는 원본에 근거한 입력·닫기·결과 탐색 화면을 재현한다. 확인된 15곳 정보로 조건에 맞는 결과를 제공하며 새 AI API를 연결하거나 실제 AI 응답·음성 인식 성공을 가장하지 않는다. 음성 입력이 필요한 미관찰 부분은 A의 확인 절차를 따른다.
- 즐겨찾기는 15곳의 시설 ID를 로컬에서 추가·해제하고 목록·상세와 연결한다. 로그인·계정 동기화는 추가하지 않는다.
- 내 이용권은 실제 발급이 없다는 상태를 유지한다. 기존 테스트 선택 기록을 실물 이용권으로 바꾸지 않는다. 내 공유도 실제 면 등록·계약 없이 확인된 화면과 조작을 재현한다.
- 구매하기 이후의 기존 로컬 테스트 종료는 유지하며 선택한 시설·상품·가격을 정확히 기록한다. 실제 결제·예약·발급이 없다는 설명을 유지한다. 테스트 선택 기록은 기존 최근 7일 정책을 따른다.
- 기존 개선 요소인 혼잡도·원천 갱신 시각·주의 문구는 유지한다. 목록은 혼잡도→주차장 이름 바로 오른쪽 갱신 시각→거리, 상세는 혼잡도와 이름 한 줄·그 아래 가운데 갱신 시각이라는 기존 합의를 따른다. 취소된 여백 변경은 되살리지 않는다.

## 5. 코드·데이터 계약과 변경 경계

- `prototype/app.js`의 조회·화면 이동·그리기 책임을 필요한 작은 모듈로 분리한다. 모든 코드를 새로 쓰지 않는다.
- `prototype/parking-map.js`의 공개 Client ID와 네이버 SDK 사용 방식을 유지한다. 성능 변경은 지도/표식 재사용과 불필요한 갱신 제거에 집중한다.
- `/api/parking`의 실제 스냅샷 계약을 유지한다. 지도 인증은 이 경로 및 DB 조회와 별개다. 브라우저에서 지도와 현황을 독립적으로 이용할 수 있게 한다.
- Supabase의 기존 3개 테이블·22개 컬럼, 수집 함수·스케줄·보관 정책을 이번 화면 개선 때문에 재설계하거나 변경하지 않는다.
- 수동으로 검증한 현장 요금·상품 조건은 기존 시설 카탈로그에 보강한다. 이번 범위에서 가격 관리용 새 DB·관리자 화면을 만들지 않는다.
- 캐시가 필요해도 원천 시각·수집 시각·조회 성공 시각을 섞지 않는다. 오래된 값을 최신으로 보이게 하는 캐시를 사용하지 않는다.
- 과거 더미 자료는 실행 경로로 되돌리지 않는다. 실제 데이터가 없으면 미확인으로 표시한다.

## 사용자 후속 확정 — AI·내 공유·검증 환경

2026-10-24. AI는 사용자의 후속 정정에 따라 관찰한 첫 화면과 닫기까지만 재현한다. 음성 입력·검색 결과·설정 상세는 이번 구현에서 제외한다. 원본 ‘듣고 있어요’ 문구는 첫 화면 예시로만 표시하고 실제 음성 입력이 실행되지 않음을 같은 화면에 명시한다. 마이크·현재위치·AI API를 호출하지 않는다. 기존 E의 AI 입력/결과 재현 요구는 이 최신 선택으로 대체한다.

내 공유의 거주자/월주차는 안내와 실제 신청 전 경계까지만 재현한다. 실제 배정 조회·동의 전송·외부 신청은 하지 않는다. 사용자는 아이폰 연결 복구를 알렸고 원본 관찰 연결을 확인했다. 프로토타입 검사는 Chrome에서 수행한다. Chrome 검증을 실제 iPhone Safari 검증으로 보고하지 않는다.

현재 위치 검색은 사용자1안승인으로 연결한다. 기존앱에Reverse Geocoding을추가하고사용자버튼클릭/브라우저권한허용뒤에만기기좌표를네이버로조회한다. 기존주소수동검색은유지하며좌표를DB/로그에보관하지않는다. 실제위치허용은사용자가직접수행한다.
