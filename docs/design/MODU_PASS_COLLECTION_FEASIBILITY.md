# 모두의주차장 주차권 5분 수집 · 가능성 조사

> 후속 실제 적용: [서버 수집 인수인계](../../supabase/MODU_PASS_HANDOFF.md). 아래는 구현 전 조사 기록이다. 현재는 서버10곳/76상품 일회·예약 저장과 화면 연결을 검증했다.

2026-10-25. 설계·일회 읽기 조사이며 수집기 배포, 예약 활성화, DB 저장은 하지 않았다.

## 확인한 사실

공개 페이지 `https://app.modu.kr/p/262904`를 로컬에서 코드로 한 번 GET했다. 응답 HTML은 93,391바이트였으며, 자바스크립트를 실행하지 않고도 본문에서 서울숲IT밸리 이름·제휴·328면과 상품 4개의 이름/가격/이용시간/상품 링크를 읽을 수 있었다.

| 상품 ID | 이름 | 가격 | 이용시간 |
|---|---|---|---|
| 15885 | 휴일 3시간권 | 3,000원 | 00:00~23:59 |
| 15884 | 휴일 5시간권 | 5,000원 | 00:00~23:59 |
| 15328 | 야간권 | 4,000원 | 17:00~23:59 |
| 15327 | 심야권 | 6,000원 | 17:00~익일 07:00 |

이는 1곳의 일회 읽기 성공이다. 목록에 보이는 4개가 전체 상품이라는 보장은 없으며, 날짜·이용시간 조건·전체보기·판매중지·할인·채널 차이는 다음 검증 대상이다. URL에 조회 날짜를 지정하지 않은 응답이므로 조회일과 상품의 적용일을 자동으로 동일시하지 않는다. 아이폰 오늘 화면에서 같은 4개 값이 보인 사실은 별도 관찰 기록에 남아 있다.

## 제안 구조

`Supabase Cron(5분) → 전용 Edge Function → 승인된 시설의 공개 웹페이지 → HTML 파싱·검증 → 주차권 현재값·변경 기록 → 화면 조회`

서울시 주차 현황 수집기와 별도 함수·결과 상태로 분리한다. 서울시 수집 성공으로 주차권 수집도 성공한 것으로 처리하지 않는다. 브라우저마다 사이트를 수집하는 구조가 아니라 서버가 수집하고 여러 화면은 DB의 같은 값을 읽도록 한다.

Supabase는 pg_cron+pg_net으로 Edge Function 예약 호출을 지원한다. 현재 저장소의 서울시 예약 SQL도 이 방식을 사용한다. 이번 조사에서 실제 원격 Cron 상태를 재조회하지 않았으므로 기존 문서의 활성화 기록을 현재 운영 성공 증거로 사용하지 않는다.

## 구현 전에 검증할 순서

1. 동일 공개 페이지를 Supabase 실행 환경에서 한 번 읽고 이름·시설 ID·상품 ID·가격·시간을 비교한다. 실패 시 예약을 만들지 않는다.
2. 확정된 15곳의 웹 시설 ID를 찾는다. 공영·민영 앱 결제 미지원은 ‘수집 실패’와 ‘해당 상품 없음’을 구분한다. 운영사·주소가 다른 신규 후보는 사용자 확인 없이 연결하지 않는다.
3. 날짜/기간 조건, 원본 전체보기, 이용 불가 카드, 판매 마감, 정상적인 빈 목록을 확인한다. 실제 결제 단계는 조사하지 않는다.
4. DB 계약을 정한다. 시설 연결(우리 UUID↔제공처 시설 ID), 상품 식별, 날짜·시간 조건별 판매 상태/가격, 원본 확인 시각, 마지막 성공, 수집 결과를 분리한다. 상품 수집 시각을 제공처 갱신 시각으로 표시하지 않는다.
5. 한 배치가 겹치지 않게 잠금·시간 제한·동시 요청 상한을 두고, 429·오류에는 간격을 늘린다. 실패 응답으로 기존 상품을 삭제하거나 0원으로 바꾸지 않는다. 파싱 구조가 바뀌면 마지막 성공값과 확인 실패 상태를 구분한다.
6. 짧은 연속 실행을 확인한 뒤 5분 예약을 활성화한다. 수집 변경 기록은 기존 선호대로 7일 보관을 제안한다. 현재 상품/시설 연결은 과거 로그가 아니므로 7일이 지났다고 삭제하지 않는다. 주차권의 ‘오래됨’ 판정 기준은 별도 합의하며 현황의 20분 규칙을 자동 적용하지 않는다.

## 예상 부하와 한계

한 함수가 배치를 처리하면 30일 기준 8,640회 실행이다. 시설별로 함수 15개를 호출하는 방식과 구분한다. 하지만 외부 웹 요청은 페이지당 별도로 발생하므로 15곳 각각 1요청이면 하루 4,320요청, 30일 129,600요청이다. 날짜·상품 상세·전체보기를 추가하면 증가한다. 실제 필요한 제휴 시설만 자주 읽고 시설 메타는 덜 읽는 방식으로 줄일 수 있다.

무료 Edge Function의 문서상 worker 최대 150초·요청 CPU 2초 제한을 고려한다. HTML 직접 읽기가 15곳 모두 가능하면 브라우저 자동 실행보다 가볍게 시작할 수 있으나 현재 전체 실행시간·전송량·DB 용량은 미측정이다. ‘무료에서 확실히 운영 가능’ 또는 ‘5분마다 가격이 갱신됨’으로 보장하지 않는다. 제공처의 수집 허용 범위·요청 제한도 예약 활성화 전에 확인한다.
