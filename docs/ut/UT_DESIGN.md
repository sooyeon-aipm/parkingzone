# 모두의주차장 — 정보 이해도 UT 설계 초안

> 2026-10-26 현재 실행 방식 안내: 온라인 UT에서 Vercel 배포 주소를 사용하며 현재 앱은 실데이터를 조회한다. 아래 2026-10-22의 가상 데이터·고정 시각·비교 모드 설명은 당시 설계로 보존한다. [GA4 설정·전체 이벤트](GA4_SETUP.md)와 [5명 참여자 링크](UT_PARTICIPANT_LINKS.md)는 구현·공개 배포·대표 화면 접속을 확인했다. GA4 측정 ID 발급·실제 수신·참여자 UT 완료와 구분한다.

기준일: 2026-10-22. 진행도/학습 선택 A2/B1/C1과 후속 UT 설계 선택 A1/B1/C1을 반영했다. 실제 사용자 테스트는 미실행이며 아래 ‘제안’은 최종 확정이 아니다.

## 확정한 목적과 현재 단계

- 진행도는 DB 설계·프로토타입·UT 준비를 영역별로 표시한다. 전체를 한 숫자로 합치지 않는다.
- 다음 학습은 UT 검증 질문·과업·판정 기준을 함께 설계하는 것이다.
- 우선 확인할 것은 ‘상태·갱신 시각·불확실성을 이해하고 선택 이유와 판단 한계를 설명하는가’다.
- 선택 속도와 대안 탐색은 이번에 우선 목표로 선택하지 않았다. 실제 테스트를 설계하면서 참고 관찰할 수 있으나 새 필수 지표로 임의 추가하지 않는다.
- 모바일 웹, 성수동 15개 기본정보+가상 상품/현황, 기존안·개선안 비교 모드, 구매하기는 로컬 선택 기록 후 종료라는 기존 합의를 유지한다. UI는 이번 작업에서 바꾸지 않는다.

검증 목적과 3상황(정상·지연·시각 미확인), 설명 3요소 관찰, 개선안 이해도부터 확인하는 방식을 합의했다. 참여자에게 줄 정확한 과업 문구·상황별 기대 설명·관찰표·모집/진행 세부는 남아 있다. 문서 작성만으로 UT 준비 완료나 학습 완료를 계산하지 않는다.

## 왜 과업과 판정 기준을 먼저 정하는가

과업은 사람에게 맡길 일, 판정 기준은 그 행동과 설명에서 무엇을 확인할지 정하는 규칙이다. 버튼이 동작하는 것은 기능 검사로 확인한다. 실제 사람이 정보를 발견하고 이해하는지는 행동·설명을 관찰해야 한다.

개선안에만 있는 정보를 기존안 사용자가 설명하지 못했다는 이유만으로 오답 처리하면 개선안에 유리한 결론을 미리 정하게 된다. 비교 UT를 선택할 경우 정보가 제공되었는지, 그 정보 안에서 정확히 판단했는지, 없는 정보까지 확신했는지를 구분해 관찰해야 한다.

‘여유 주차장을 골랐는가’만으로 이해도를 판단하지 않는다. 가격·거리·다른 제약을 고려한 선택도 가능하다. 선택한 시설보다 그 이유와 설명이 화면 근거에 맞는지 확인한다.

## 참여자에게 줄 과업 예시 — 제안

먼저 이 화면이 가상 상품·현황을 사용하는 연구용 모형임을 안내한다. 테스트 상황의 시각은 고정 12:00 KST이며 실제 벽시계 시각과 구분한다.

> 테스트 상황은 오늘 낮 12시입니다. 성수동에서 이용할 주차장을 골라주세요. 선택을 마치면 알려주세요.

자유 탐색 중에 ‘혼잡도와 갱신 시각을 보세요’ 같은 힌트를 먼저 주지 않는다. 선택 후 중립 질문 예시는 다음과 같다.

> 어떤 정보를 근거로 선택하셨나요?
> 이 화면을 보고 확실히 알 수 있는 것과 아직 알 수 없는 것은 무엇인가요?

이 예시 문구 자체는 확정 과업이 아니다. 구매를 보류하는 판단도 관찰 대상이 될 수 있으며 구매 버튼 클릭만으로 이해 성공을 판정하지 않는다. 구매를 선택한다면 기존 합의대로 버튼은 로컬 선택 기록 후 테스트를 종료한다. 이유·이해도는 진행자가 별도 관찰표에 기록해야 한다.

## A. 상황 범위 — 1안 확정 (나머지는 이전 대안)

1. 추천: 정상·갱신 지연·원천 시각 없음 3상황. 일반적인 정보 해석과 ‘과거 기록/기준 시각 미확인’의 차이를 먼저 확인한다.
2. 정상 1상황만. 기본 정보를 이해하는지 빠르게 확인하지만 예외 이해는 알 수 없다.
3. 정상·갱신 지연·원천 시각 없음·조회 실패·최근 기록 없음 5상황. 범위는 넓지만 반복 노출에 따른 익숙해짐·부담을 관리해야 한다.
4. 기타: 사용자 직접 작성.

## B. 이해도 판정 방식 — 1안 확정 (나머지는 이전 대안)

1. 추천: 설명을 3요소로 나눠 관찰한다. 상태/면수의 의미, 정보의 기준 시점, 도착 시 입차 보장 여부를 각각 ‘정확·오해·설명 없음’으로 기록하고 자발 설명/중립 질문 후/힌트 후를 구분한다. 같은 단어를 말했는지가 아니라 의미를 판단한다.
2. 짧은 선택형 질문으로 확인한다. 채점은 쉽지만 정답을 보고 알아맞히는 반응과 스스로 이해한 반응이 섞일 수 있다.
3. 자유 설명만 수집하고 정량 판정은 보류한다. 예상하지 못한 해석을 발견하기 좋지만 명확한 성공률을 바로 계산하기 어렵다.
4. 기타: 사용자 직접 작성.

추천 관찰 기준도 최종 합격선·참여자 수·목표 성공률이 아니다. 상황별 기대 설명과 오해 예시, 진행자의 도움 기준은 선택 후 함께 구체화한다. 시각 미확인/기록 없음 상황에서 숫자나 최신성을 알 수 없다고 설명하는 것은 올바른 이해가 될 수 있다.

## C. 첫 UT 진행 방식 — 1안 확정 (나머지는 이전 대안)

1. 추천: 개선안 이해도부터 확인하고, 결과를 보고 기존안 비교 UT를 설계한다. 현재 우선 질문인 ‘이 화면을 이해하는가’에 집중한다. 이것만으로 기존안보다 개선됐다고 주장하지 않는다. 기존안 비교 모드는 그대로 둔다.
2. 같은 참여자가 기존안·개선안을 모두 사용하고 보는 순서를 번갈아 배치한다. 개인 차이를 줄일 수 있지만 같은 정보의 반복 노출·앞선 질문의 학습 영향을 기록해야 한다. 정답 설명은 두 조건을 마친 뒤 제공한다.
3. 참여자를 나눠 각자 한 안만 사용하게 한다. 앞선 화면의 영향을 줄일 수 있지만 두 집단의 경험 차이와 모집 부담을 고려해야 한다.
4. 기타: 사용자 직접 작성.

## 선택 후 이어서 정할 것

선택한 상황별 과업·기대 설명·관찰표, 목표 참여자의 조건과 모집 가능 인원, 진행자/관찰자 역할, 실제 시작·종료 방법을 다음 묶음에서 제안한다. 정해지지 않은 참여자 수·성공률·시간 제한을 임의로 확정하지 않는다. 실제 사용자 UT/모집/분석을 실행하지 않았다.

## 마감 범위와 분리

사용자는 1/1/1을 선택한 뒤 ‘23일까지 해야 하는 과제 목표는 다 했는가’를 확인했다. 23일 14시 목표는 DB·컬럼·수집부터 화면까지의 구현 설계 설명과 최소 3개 더미데이터의 UT 가능한 동작 프로토타입 준비다. 실제 UT 실시·분석이나 최종 제안서 완성까지 필수로 확정한 것이 아니다. 실제 DB 저장·자동 수집 실행도 기존 보류를 유지한다. UT 설계/실행의 모든 항목을 새 마감 필수로 자동 확대하지 않는다.

## 최신 상태 — 기본 산출물 준비, 유미·종현 확인, 수연 검토 대기

사용자는 참여자용 보기 추가(1안)를 선택하고 최종 검토 선택 B3에 ‘유미·종현만 확인, 수연에게 바로 검토받을 예정’이라고 명시했다. 두 팀원의 기존 결과물 확인과 수연 최종 승인을 구분한다. 참여자용 보기 추가는 구현·Chrome 검사 완료이며 수연 검토 대상에 포함한다. 기본 산출물은 준비되어 수연 검토를 요청할 수 있다. [수연 검토 자료](../review/SUYEON_REVIEW.md)를 따른다. 실제 사용자 UT·실제 DB/자동 수집은 미실행/기존 보류를 유지한다. 전체 진행률 50%/80%를 재사용하지 않는다.
