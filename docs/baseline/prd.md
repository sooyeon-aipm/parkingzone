## 1. 프로젝트 개요

---

### 한 줄 정의

성수동 주차장 실시간 현황 서비스

### 제품 목표

출발 전이나 이동 중 주차장을 확인하려는 개인 운전자가 성수동 주차장의 실시간 주차가능면수, 전체 주차면수, 혼잡 상태, 마지막 수집 시각을 빠르게 확인하고 주차장 선택과 이동 계획을 판단할 수 있게 한다. 이를 통해 주차권을 구매하고 방문했다가 만차로 주차에 실패하는 문제와 시간 낭비를 줄인다. 이후 단계에서는 축적된 데이터로 예상 도착 시점의 만차 가능성을 참고 정보로 제공한다. MVP에서는 수익화하지 않고 무료 정보 제공에 집중한다.

### 배경

모두의주차장 개선 프로젝트는 주차장 정보를 알지 못한 채 주차권을 구매하고 방문한 사용자가 만차로 주차에 실패하는 문제를 해결하기 위해 시작되었다. 당초 서울시 영주차장 정보 공공 API로 구현하려 했으나 이 데이터가 실시간 주차면수를 제공하지 않는 한계를 발견했다. 그래서 서울주차정보시스템 홈페이지 화면을 크롤링해 실시간 주차가능면수를 수집하는 방식으로 변경한다. MVP는 성수동 주차장에 한정하며, 주차장 목록·전체면수·현재 가능면수·혼잡 상태·마지막 업데이트 시각·수집 실패 또는 정보 없음 안내를 중심으로 구성한다. 수익 모델은 MVP 단계에서 설정하지 않는다. 기존 PRD의 도착 시점 만차 예측은 상태 이력이 충분히 쌓인 이후 고도화 단계에서 제공한다.

### 사용자 문제

운전자는 주차장을 선택하거나 주차권을 구매한 뒤 실제 도착했을 때 만차인지 알기 어려워 주차에 실패하고 불필요한 이동과 대기 시간을 겪는다. 기존 공공 API는 실시간 주차면수를 제공하지 않고, 기존 주차 정보는 현재 상태만 보여주거나 갱신 시각이 불명확해 정보의 신뢰도를 판단하기 어렵다. 외부 데이터의 갱신 지연으로 도착 시점의 실제 상태와 화면 표시가 다를 수 있다.

### 해결 방안

서울주차정보시스템 화면에서 성수동 주차장의 주차장명, 주소, 주차장 코드(PKLT_CD), 전체 주차면수, 주차가능면수, 수집 시각을 5~10분 주기로 자동 수집한다. 수집 데이터는 PKLT_CD 기준으로 중복을 제거하고 숫자 형식을 검증하며, 정보수집중·미연계·수집실패 상태를 구분하고 마지막 정상 수집값과 수집 시각을 저장한다. 사용자에게는 성수동 주차장 목록에서 전체면수, 현재 가능면수, 혼잡 상태, 마지막 업데이트 시각을 보여주고, 오래된 데이터에는 '최신 정보 아님'을, 수집 실패나 정보 없음에는 안내를 표시한다. 반복 수집은 고정된 자동화 코드로 운영하고, AI는 초기 사이트 구조 분석·예외 처리·데이터 이상 탐지에 활용한다. 후속 단계에서는 상태 이력을 활용해 예상 도착 시점의 만차 가능성을 참고 정보로 제공한다.

### 차별점

현재 가능 대수만 보여주는 서비스와 달리 현재 상태와 마지막 수집 시각을 함께 제공해 사용자가 정보의 최신성을 직접 판단할 수 있다. 공공 API에 없는 실시간 주차가능면수를 서울주차정보시스템 화면 수집으로 확보한다. 반복 수집은 고정된 자동화 코드로 안정적으로 운영하고 AI는 구조 분석·예외 처리·이상 탐지에만 활용해 비용과 판단 편차를 줄인다. 후속 단계에서는 목적지 주차장 기준으로 예상 도착 시점의 만차 가능성을 제공해 상태 확인을 이동 의사결정으로 연결한다.

### 타겟 사용자

목적지로 운전 중이거나 출발 전 주차장을 미리 확인하려는 개인 운전자. 초기에는 성수동을 방문하는 운전자가 대상이며, 도심·상업지구·관광지·병원·관공서처럼 주차 수요가 높은 지역을 자주 방문한다. 주차권을 구매한 뒤 도착해서 만차를 확인하는 상황을 피하고 싶어 한다. 모바일 사용에 익숙하지만 복잡한 설정은 선호하지 않으며, 빠르게 주차장 상태와 정보 갱신 시각을 확인해 대체 주차장 선택 여부를 판단하려 한다. 내부 사용자로는 수집 현황을 점검하는 데이터 운영자와 서비스 전반을 관리하는 서비스 관리자가 있다.

### 사용자 시나리오

운전자는 이동 전 또는 운전 중 서비스에서 성수동 주차장 목록을 열거나 주차장명·지역으로 검색한다. 목록에서 주차장별 전체면수, 현재 가능면수, 혼잡 상태, 마지막 업데이트 시각을 확인하고 방문할 주차장을 선택한다. 상태가 여유이면 해당 주차장으로 이동하고, 만차이거나 혼잡하면 다른 주차장을 검토한다. 데이터가 오래되었거나 수집에 실패한 경우 '최신 정보 아님' 또는 수집 실패·정보 없음 안내와 마지막 정상 수집 시각을 확인한 뒤 최종 결정을 내린다. 데이터 운영자는 운영 화면에서 주차장별 수집 성공 시각과 오류 상태를 확인하고 사이트 구조 변경이나 이상 데이터를 점검한다. 후속 단계에서는 현재 위치 기준 예상 도착 시점의 만차 가능성도 확인한다.

### 핵심 지표

MVP 완료 조건: 성수동 주차장 목록이 표시되고, 주차가능면수가 정상 저장·표시되며, 같은 주차장이 중복 표시되지 않고, 수집 시각과 오류 상태를 확인할 수 있다. 핵심 KPI는 주차 상태 조회 완료율, 주차장 검색 후 상태 확인까지 걸리는 평균 시간, 주차장 상태 정보의 최신 갱신 비율, 주차장 데이터 수집 성공률, 갱신 오류 감지율이다. 고도화 단계에서는 도착 시점 만차 예측의 정확도와 정밀도, 예측 결과 제공 가능 비율, 주차장 재검색 또는 대체 주차장 선택률을 추가 측정한다.

### 리스크

서울주차정보시스템 화면 구조가 바뀌거나 접근이 제한되면 크롤링이 실패해 실제 상태와 표시 상태가 달라질 수 있다. 화면 수집 방식의 이용 약관·법적 허용 여부 확인이 필요하다. 갱신 지연이나 수집 실패 시 오래된 데이터를 최신으로 오인할 수 있으므로 마지막 수집 시각과 '최신 정보 아님' 표시를 반드시 제공해야 한다. 주차장별 데이터 품질이 달라 미연계·정보 없음 주차장이 있을 수 있고, 과거 이력이 부족하면 후속 예측을 제공하기 어렵거나 정확도가 낮을 수 있다. 상태와 예측 결과를 주차 가능 보장으로 오해할 위험이 있어 참고 정보임을 안내해야 하며, 운전 중 화면 조작은 안전사고 위험이 있으므로 이동 중 사용을 최소화하고 정차 후 이용 또는 음성 안내를 유도해야 한다. MVP는 성수동에 한정되어 지역 확장 시 추가 검증이 필요하다.

## 1. 주차장 검색 및 선택

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중
>

운전자가 성수동 주차장 목록을 보거나 지역명·주차장명으로 검색해 특정 주차장을 선택하는 영역이다. MVP 범위는 서울주차정보시스템에서 수집하는 성수동 주차장이며, 지도 기반 탐색과 타 지역 확장은 후속 단계로 둔다.

**수용 기준:**

```
1. ○ 성수동 주차장 목록이 표시된다.
2. ○ 사용자는 주차장명 또는 지역을 기준으로 주차장을 검색할 수 있다.
3. ○ 검색 결과에는 MVP에서 수집·지원하는 성수동 주차장만 표시되고 같은 주차장이 중복 표시되지 않는다.
4. ○ 검색 결과가 없거나 데이터가 제공되지 않으면 그 이유와 대체 검색 방법이 안내된다.
```

### 1.1 성수동 주차장 목록 조회

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**기능의 근거**: MVP 완료 조건이 성수동 주차장 목록 표시이며, 운전자가 한눈에 여러 주차장의 상태를 비교해야 대체 주차장을 판단할 수 있다.

운전자가 서비스에 진입하면 MVP 지원 범위인 성수동 주차장을 목록으로 확인한다. 각 항목에 주차장명, 전체면수, 현재 가능면수, 혼잡 상태, 마지막 업데이트 시각을 보여주며, 타 지역 목록은 범위 밖이다.

**개발 준비 슬롯**

- **선행조건**: - 서울주차정보시스템에서 수집해 정제한 성수동 주차장 데이터가 서비스 데이터에 존재한다.
- **트리거**: - 운전자가 Mobile 또는 Web에서 서비스에 진입한다.
- **동작**: - 서비스는 PKLT_CD 기준으로 중복이 제거된 성수동 주차장을 조회해 목록으로 표시한다.
- **결과**: - 목록의 각 항목에 주차장명, 전체면수, 현재 가능면수, 혼잡 상태, 마지막 업데이트 시각이 표시된다.
    - 같은 주차장은 목록에 한 번만 표시된다.
- **예외**: - 수집 실패 또는 정보 없음 상태의 주차장은 임의 수치 대신 해당 안내를 표시한다.
- **표시**: - 목록 항목은 상태 배지와 마지막 업데이트 시각을 함께 보여준다.
- **비즈니스 규칙**: - 목록에는 MVP 지원 범위인 성수동 주차장만 포함한다.

### 1.2 주차장명·지역 검색

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**기능의 근거**: 운전자는 방문할 지역이나 특정 주차장을 먼저 찾은 뒤 상태를 확인한다.

운전자가 주차장명 또는 지역명을 입력해 지원 범위 내 주차장을 검색한다. 결과가 없거나 데이터가 제공되지 않으면 이유와 대체 검색 방법을 안내하며, 지도 기반 탐색은 별도 기능이다.

**성공 기준**: 특정 주차장 검색 후 상태 확인까지 걸리는 평균 시간을 줄인다.

**개발 준비 슬롯**

- **선행조건**: - 검색 대상인 성수동 주차장 데이터가 서비스에 존재한다.
- **트리거**: - 운전자가 검색창에 주차장명 또는 지역명을 입력하고 검색을 실행한다.
- **동작**: - 서비스는 지원 범위 내 주차장 중 입력어와 일치하는 주차장을 찾아 결과로 표시한다.
    - 운전자가 결과에서 주차장을 선택하면 상세 상태 화면으로 이동한다.
- **결과**: - 결과 목록에 일치하는 주차장이 표시되며 같은 주차장은 중복 표시되지 않는다.
- **예외**: - 검색 결과가 없거나 데이터가 제공되지 않으면 그 이유와 대체 검색 방법을 안내한다.
- **비즈니스 규칙**: - 검색 결과에는 MVP에서 수집·지원하는 성수동 주차장만 표시한다.

### 1.3 주차장 상세 화면

> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**기능의 근거**: 운전자는 선택한 주차장의 위치와 데이터 출처를 확인하고 방문 여부를 판단해야 한다.

운전자가 목록이나 검색 결과에서 선택한 주차장의 위치, 주차장명, 지원 데이터 범위 등 기본 정보와 현재 상태를 한 화면에서 확인한다. 상태·시각 표시 상세는 현재 주차 상태 요구사항에서 다룬다.

**개발 준비 슬롯**

- **선행조건**: - 운전자가 목록 또는 검색 결과에서 주차장을 선택한다.
- **트리거**: - 운전자가 목록 또는 검색 결과의 주차장 항목을 선택한다.
- **결과**: - 상세 화면에 주차장명, 위치(주소), 지원 데이터 범위, 현재 상태와 마지막 업데이트 시각이 표시된다.
- **예외**: - 선택한 주차장의 최신 상태를 확인할 수 없으면 확인 불가 안내와 마지막 정상 수집 시각을 표시한다.

### 1.4 지도 기반 주차장 탐색 (후속 단계)

> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**기능의 근거**: 기존 명세에서 지역명·주차장명 검색과 함께 지도 기반 탐색이 언급되었다.

운전자가 지도에서 주차장 위치를 보며 탐색하고 선택하는 기능으로, 기존 기능명세서의 탐색 방식 중 하나이다. MVP 화면 구성에는 포함되지 않아 후속 단계에서 도입 여부와 시점을 정한다.

**개발 준비 슬롯**

- **트리거**: - 운전자가 지도 탐색 화면에 진입한다.
- **결과**: - 지도의 주차장 마커에서 주차장을 선택하면 상세 상태 화면으로 이동한다.

## 2. 현재 주차 상태 및 갱신 시각 표시

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중
>

운전자가 주차장의 전체 주차면수, 현재 주차가능면수, 혼잡 상태 배지, 마지막 업데이트 시각을 확인하는 영역이다. 현재 상태를 판단할 수 없으면 임의 상태를 표시하지 않으며, 도착 시점 예측은 별도 영역에서 다룬다.

**수용 기준:**

```
1. ○ 주차장 목록과 상세에서 전체면수와 현재 가능면수가 표시된다.
2. ○ 혼잡 상태가 여유·혼잡·만차 배지로 표시된다.
3. ○ 마지막 업데이트 시각이 한국 시간 기준으로 함께 표시된다.
4. ○ 현재 상태를 판단할 수 없으면 임의 상태 대신 확인 불가가 안내된다.
```

### 2.1 현재 주차 상태 확인

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**기능의 근거**: 운전자는 출발 전 또는 이동 중 현재 주차 가능 여부를 빠르게 판단해야 한다.

운전자가 주차장의 현재 혼잡 상태와 마지막 업데이트 시각, 전체·가능 주차면수를 확인한다. 상태를 확인할 수 없을 때는 추정 상태를 표시하지 않으며, 도착 시점 예측은 별도 기능이다.

**성공 기준**: 주차 상태 조회 완료율과 최신 갱신 비율을 높인다.

**개발 준비 슬롯**

- **선행조건**: - 선택한 주차장에 최신 또는 최근 수집된 상태 데이터가 존재한다.
- **트리거**: - 운전자가 주차장 목록 또는 주차장 상세 화면을 연다.
- **결과**: - 서비스는 여유·혼잡·만차 중 하나의 현재 상태와 마지막 확인 시각을 표시한다.
    - 서비스는 주차 상태 조회 완료 이벤트를 기록한다.
- **예외**: - 현재 상태를 판단할 수 없는 경우 임의 상태 대신 확인 불가로 표시한다.

#### 2.1.1 혼잡 상태 배지와 마지막 업데이트 시각 표시

운전자가 선택한 주차장의 현재 상태를 여유·혼잡·만차 배지로, 마지막 업데이트 시각을 한국 시간 기준으로 함께 보여준다. 판단 불가 시에는 배지 대신 확인 불가를 표시한다.

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**개발 준비 슬롯**

- **선행조건**: - 선택한 주차장의 상태 데이터와 마지막 확인 시각이 존재한다.
- **결과**: - 현재 상태는 여유·혼잡·만차 배지로 표시한다.
    - 마지막 업데이트 시각은 한국 시간 기준으로 표시한다.
- **예외**: - 상태 데이터가 없거나 유효하지 않으면 확인 불가 상태와 사유를 표시한다.
- **표시**: - 상태 배지와 마지막 업데이트 시각을 함께 표시해 정보 최신성을 판단할 수 있게 한다.

#### 2.1.2 전체·가능 주차면수 및 상태 산정 기준 확인

운전자가 주차장의 전체 주차면수와 현재 가능면수를 보고, 상태 산정 기준이 있으면 함께 확인한다. 면수는 수집된 값이 있을 때만 표시한다.

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**개발 준비 슬롯**

- **선행조건**: - 수집된 전체 주차면수와 주차가능면수가 존재한다.
- **결과**: - 목록과 상세 화면에 전체 주차면수와 현재 가능면수가 표시된다.
    - 상태 산정 기준이 있는 경우 상세 화면에서 산정 기준을 확인할 수 있다.
- **예외**: - 면수 값이 없거나 유효하지 않으면 임의 값 대신 정보 없음을 표시한다.

## 3. 주차 데이터 수집 및 정제

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중
>

서울주차정보시스템 화면에서 성수동 주차장 데이터를 고정된 자동화 코드로 주기 수집하고, 중복 제거·숫자 검증·수집 상태 구분·마지막 정상값 저장으로 서비스용 데이터를 만드는 영역이다. 공공데이터 API 연동은 실시간 주차면수 미제공으로 제외하며, 성수동 외 지역 수집은 범위 밖이다.

**수용 기준:**

```
1. ○ 성수동 검색 결과에서 주차장명, 주소, 주차장 코드, 전체 주차면수, 주차가능면수, 수집 시각이 수집된다.
2. ○ PKLT_CD 기준으로 중복이 제거되고 숫자 형식이 검증된 값만 저장된다.
3. ○ 정보수집중·미연계·수집실패 상태가 구분되어 기록되고 마지막 정상 수집값과 수집 시각이 저장된다.
4. ○ 5~10분 주기로 갱신되며 실패 시 재시도된다.
```

### 3.1 성수동 주차장 정보 주기 수집

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 데이터 운영자 | **기기**: Web
>

**기능의 근거**: 공공 API가 실시간 주차면수를 제공하지 않아 서울주차정보시스템 화면에서 직접 수집해야 한다.

서비스가 서울주차정보시스템 화면에서 '성수동'을 검색해 주차장명, 주소, 주차장 코드, 전체 주차면수, 주차가능면수, 수집 시각을 고정된 자동화 코드로 주기 수집한다. 반복 수집에 AI의 건별 판단은 쓰지 않으며, 성수동 외 지역과 공공데이터 API 연동은 범위 밖이다.

**성공 기준**: 지원 범위 내 주차장 데이터 수집 성공률을 높인다.

**개발 준비 슬롯**

- **선행조건**: - 서울주차정보시스템 화면의 구조 분석이 끝나 수집 코드가 마련되어 있다.
- **트리거**: - 설정된 수집 일정에 따라 5~10분 주기로 수집이 자동 실행된다.
- **동작**: - 서비스는 서울주차정보시스템에서 성수동을 검색한다.
    - 서비스는 결과에서 주차장명, 주소, 주차장 코드, 전체 주차면수, 주차가능면수, 수집 시각을 추출한다.
    - 추출한 값은 정제 단계로 전달한다.
- **예외**: - 수집이 실패하면 재시도하고 최종 실패 시 수집실패로 기록한다.
    - 응답 지연, 필수 필드 누락, 화면 형식 변경이 발생하면 해당 수집 건을 비정상으로 기록한다.
- **비즈니스 규칙**: - 반복 수집은 고정된 자동화 코드로 수행하고 AI에게 매번 데이터를 직접 판단시키지 않는다.
    - 수집 대상은 서울주차정보시스템의 성수동 주차장으로 한정한다.
- **데이터**: - 수집 항목은 주차장명, 주소, 주차장 코드(PKLT_CD), 전체 주차면수, 주차가능면수, 수집 시각이다.

#### 3.1.1 수집 실패 재시도

주기 수집이 실패하면 서비스가 자동으로 재시도하고, 최종 실패 시 수집실패로 기록해 사용자 안내와 운영 점검에 연결한다.

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 데이터 운영자 | **기기**: Web
>

**개발 준비 슬롯**

- **트리거**: - 주기 수집 중 오류, 응답 지연 또는 필수 필드 누락으로 수집이 실패한다.
- **동작**: - 서비스는 실패한 수집을 재시도한다.
    - 재시도가 모두 실패하면 해당 수집을 수집실패로 기록하고 마지막 정상 수집값을 유지한다.
- **결과**: - 재시도 성공 시 최신 수집값이 반영되고 실패 시 수집실패 상태와 마지막 정상 수집 시각이 기록된다.

### 3.2 수집 데이터 정제 및 검증

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 데이터 운영자 | **기기**: Web
>

**기능의 근거**: 같은 주차장이 중복 표시되거나 잘못된 수치가 노출되면 서비스 신뢰도가 떨어진다.

수집한 데이터를 PKLT_CD 기준으로 중복 제거하고 면수의 숫자 형식을 검증해 서비스용 데이터로 반영한다. 필수 정보가 누락되거나 유효하지 않은 값은 사용자 표시용 최신 상태로 반영하지 않는다.

**성공 기준**: 같은 주차장이 중복 표시되지 않고 주차가능면수가 정상 저장·표시된다.

**개발 준비 슬롯**

- **트리거**: - 주기 수집이 완료되어 추출 결과가 전달된다.
- **동작**: - 서비스는 PKLT_CD 기준으로 중복 항목을 제거한다.
    - 서비스는 전체 주차면수와 주차가능면수의 숫자 형식을 검증한다.
    - 검증을 통과한 값만 서비스 조회 데이터에 반영한다.
- **결과**: - 정상 값은 최신 주차장 상태로 저장되고 사용자 화면에 반영된다.
- **예외**: - 숫자 형식이 아니거나 필수 필드가 누락된 값은 비정상으로 기록하고 최신 데이터로 반영하지 않는다.
- **데이터**: - 중복 판단의 유니크 키는 PKLT_CD이다.
    - 전체 주차면수와 주차가능면수는 숫자 값이다.

### 3.3 수집 상태 구분 및 마지막 정상값 보존

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 데이터 운영자 | **기기**: Web
>

**기능의 근거**: 수집이 실패해도 마지막 정상 값과 시각을 알아야 사용자가 정보의 최신성을 판단할 수 있다.

서비스가 주차장별 수집 결과를 정보수집중·미연계·수집실패 상태로 구분해 기록하고, 마지막 정상 수집값과 수집 시각을 따로 저장한다. 수집이 실패해도 마지막 정상값을 보존해 사용자 안내와 운영 점검에 사용한다.

**성공 기준**: 수집 시각과 오류 상태를 확인할 수 있다.

**개발 준비 슬롯**

- **트리거**: - 주차장별 수집 시도가 끝날 때마다 결과가 판정된다.
- **동작**: - 서비스는 수집 결과를 정보수집중·미연계·수집실패 중 해당 상태로 구분해 기록한다.
    - 정상 수집이면 값과 수집 시각을 마지막 정상 수집값으로 갱신한다.
    - 수집 실패 시 마지막 정상 수집값은 덮어쓰지 않고 유지한다.
- **결과**: - 주차장별로 수집 상태, 마지막 정상 수집값, 마지막 정상 수집 시각이 저장된다.
- **데이터**: - 저장 항목은 PKLT_CD, 주차장명, 주소, 전체 주차면수, 주차가능면수, 수집 시각, 수집 상태(정보수집중·미연계·수집실패), 마지막 정상 수집값, 마지막 정상 수집 시각이다.

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중
>

데이터 운영자가 주차장별 수집 성공 시각과 오류 상태를 확인하고, AI를 활용해 사이트 구조 변경·예외·이상 데이터를 탐지하는 운영 영역이다. 반복 수집 자체는 AI가 아닌 고정 코드가 수행하며, 제공처 계약이나 자동 복구 정책 수립은 초기 범위에서 제외한다.

**수용 기준:**

```
1. ○ 운영자는 주차장별 최근 수집 성공 시각과 오류 상태를 확인할 수 있다.
2. ○ 수집 현황은 정상·지연·오류로 구분되어 표시된다.
3. ○ 사이트 구조 변경이나 비정상 수치가 감지되면 운영자가 확인할 수 있다.
```

### 4.1 주차장별 수집 현황 조회

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 데이터 운영자 | **기기**: Web
>

**기능의 근거**: 지연·오류·구조 변경을 빠르게 발견해야 사용자에게 오래된 정보를 최신처럼 보여주지 않을 수 있다.

데이터 운영자가 운영 화면에서 주차장별 최근 수집 성공 시각과 오류 상태를 조회한다. 운영 점검용 상태 확인에 한정하며 사용자용 주차장 상세는 포함하지 않는다. 제공처 계약과 자동 복구 정책 수립은 초기 범위에서 제외한다.

**성공 기준**: 데이터 갱신 오류 감지율을 높인다.

**개발 준비 슬롯**

- **선행조건**: - 데이터 운영자 권한으로 운영 화면에 접근한다.
- **트리거**: - 데이터 운영자가 운영 화면에서 수집 현황 조회를 실행한다.
- **결과**: - 운영 화면이 주차장별 최근 수집 성공 시각과 현재 오류 상태를 표시한다.
- **예외**: - 수집 이력이 없는 주차장은 수집 이력 없음으로 표시한다.
- **표시**: - 주차장별 최근 수집 성공 시각과 상태를 정상·지연·오류로 구분해 목록으로 표시한다.
- **권한 & 접근**: - 데이터 운영자만 수집 현황과 오류 이력을 조회할 수 있다.
- **데이터**: - 조회 항목은 주차장 코드, 주차장명, 최근 수집 성공 시각, 수집 상태, 오류 이력이다.

### 4.2 AI 기반 사이트 구조 분석 및 데이터 이상 탐지

> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 데이터 운영자 | **기기**: Web
>

**기능의 근거**: 화면 수집 방식은 사이트 구조가 바뀔 때 실패하기 쉽고, AI를 매 수집마다 쓰면 비용과 편차가 커진다.

서울주차정보시스템 화면의 초기 구조 분석, 수집 중 예외 처리, 비정상 데이터 탐지에만 AI를 활용해 운영자가 문제를 빠르게 알아차리게 한다. 반복 수집 자체는 고정된 자동화 코드가 담당하고 AI가 매번 데이터를 직접 판단하지 않는다.

**개발 준비 슬롯**

- **트리거**: - 초기 수집 구현 시 사이트 구조 분석을 수행한다.
    - 수집 중 예외가 발생하거나 비정상 데이터가 감지되면 AI 분석을 실행한다.
- **동작**: - AI는 초기 사이트 구조를 분석해 수집 대상 필드를 파악한다.
    - AI는 수집 예외와 비정상 데이터의 원인 후보를 분석한다.
- **결과**: - 사이트 구조 변경 의심과 비정상 데이터가 운영자가 확인할 수 있는 상태로 남는다.
- **권한 & 접근**: - 데이터 운영자만 탐지 결과를 확인할 수 있다.
- **비즈니스 규칙**: - 반복 수집은 고정된 자동화 코드로 설계하고 AI는 사이트 구조 분석·예외 처리·데이터 이상 탐지에만 활용한다.

## 5. 데이터 지연 및 오류 안내

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중
>

수집 지연·실패·정보 없음 상황에서 운전자가 정보의 신뢰도를 판단하도록 마지막 정상 수집 시각과 주의 문구를 표시하는 영역이다. 데이터 자체를 복구하는 기능은 포함하지 않으며 정보의 최신성과 한계를 전달하는 데 한정한다.

**수용 기준:**

```
1. ○ 오래된 데이터에는 '최신 정보 아님'이 표시되고 마지막 정상 수집 시각이 함께 보인다.
2. ○ 수집 실패 또는 정보 없음 시 해당 사실과 확인 불가 안내가 표시된다.
3. ○ 오래된 상태 데이터가 최신 정보처럼 표시되지 않는다.
4. ○ 상태 정보가 주차 가능을 보장하지 않는다는 안내가 제공된다.
```

### 5.1 데이터 신뢰도 안내

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**기능의 근거**: 외부 화면 수집 데이터의 지연이나 실패로 표시 정보가 실제와 다를 수 있어 운전자가 신뢰도를 직접 판단할 수 있어야 한다.

운전자가 주차 상태를 볼 때 데이터 지연, 수집 실패, 정보 없음 상태와 참고 정보 안내를 함께 확인한다. 데이터 자체를 복구하는 기능은 포함하지 않고 정보의 최신성과 한계를 전달하는 데 한정한다.

**성공 기준**: 오래된 데이터의 최신 정보 오인과 상태 조회 중 이탈을 줄인다.

**개발 준비 슬롯**

- **결과**: - 데이터가 지연되거나 오류인 경우 마지막 정상 확인 시각과 데이터 상태를 표시한다.
- **예외**: - 최신 상태를 확인할 수 없을 때 오래된 상태를 최신 정보처럼 표시하지 않는다.
- **표시**: - 상태 정보가 주차 가능성을 보장하지 않는다는 안내를 표시한다.

#### 5.1.1 최신 정보 아님·수집 실패 상태 표시

운전자가 데이터가 오래되었거나 수집에 실패한 주차장을 볼 때 '최신 정보 아님' 또는 수집 실패·정보 없음 안내와 마지막 정상 수집 시각을 확인한다. 오래된 데이터를 최신처럼 보이지 않게 한다.

> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile, Web
>

**개발 준비 슬롯**

- **선행조건**: - 선택한 주차장 데이터가 지연, 수집실패 또는 정보 없음으로 판정된다.
- **결과**: - 오래된 데이터는 '최신 정보 아님' 표시와 마지막 정상 수집 시각과 함께 표시된다.
    - 수집 실패 또는 정보 없음 주차장에는 해당 사실과 확인 불가 안내가 표시된다.
- **예외**: - 마지막 정상 확인 시각도 없는 경우 데이터 확인 불가 상태를 표시한다.
- **표시**: - 최신 상태를 확인할 수 없다는 안내와 주차 가능 여부가 보장되지 않는다는 문구를 표시한다.

### 5.2 운전 중 이용 안전 안내

> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile

**개발 준비 슬롯**

- **표시**: - 이동 중 사용을 최소화하고 정차 후 이용 또는 음성 안내를 권장하는 문구를 표시한다.

## 6. 도착 시점 만차 가능성 예측 (후속 단계)

> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중
>

운전자가 목적지 주차장을 선택하면 현재 위치 기준 예상 도착 시점의 만차 가능성을 참고 정보로 제공하는 후속 단계 영역이다. 축적된 상태 이력과 시간대별 데이터를 활용하며 MVP 범위에는 포함하지 않는다.

**수용 기준:**

```
1. ○ 예측에 필요한 데이터가 충분하면 예상 도착 시점의 만차 가능성이 제공된다.
2. ○ 데이터가 부족하면 예측 결과 대신 데이터 부족 또는 참고 제한 상태가 표시된다.
3. ○ 예측 결과가 주차 가능 보장이 아닌 참고 정보임이 안내된다.
```

### 6.1 예상 도착 시점 산정

> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile
>

**기능의 근거**: 도착 시점의 만차 가능성을 안내하려면 운전자가 언제 도착하는지 먼저 알아야 한다.

운전자가 목적지 주차장을 선택하면 현재 위치와 주차장 위치를 바탕으로 예상 도착 시점을 산정한다. 후속 단계 기능이며 MVP에는 포함하지 않는다.

**개발 준비 슬롯**

- **선행조건**: - 운전자가 목적지 주차장을 선택했다.
    - 운전자의 현재 위치를 알 수 있다.
- **동작**: - 서비스는 현재 위치와 주차장 위치를 바탕으로 예상 도착 시점을 산정한다.
- **결과**: - 산정된 예상 도착 시점이 만차 가능성 안내의 기준 시각으로 사용된다.

### 6.2 만차 가능성 안내

> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 운전자 | **기기**: Mobile
>

**기능의 근거**: 이동 중 주차장이 만차로 바뀔 수 있어 현재 상태만으로는 도착 시점의 의사결정이 어렵다.

축적된 상태 이력과 시간대별 데이터를 활용해 예상 도착 시점의 만차 가능성을 참고 정보로 안내한다. 데이터가 부족하면 예측 대신 데이터 부족 또는 참고 제한 상태를 표시하며, 주차 가능 보장으로 표현하지 않는다. MVP에는 포함하지 않는다.

**성공 기준**: 도착 시점 만차 예측의 정확도와 정밀도, 예측 결과 제공 가능 비율을 측정해 개선한다.

**개발 준비 슬롯**

- **선행조건**: - 해당 주차장의 상태 이력과 시간대별 데이터가 예측에 충분히 축적되어 있다.
- **동작**: - 서비스는 예상 도착 시점의 요일·시간대 이력을 기반으로 만차 가능성을 계산한다.
- **예외**: - 예측에 필요한 데이터가 부족하면 예측 결과 대신 데이터 부족 또는 참고 제한 상태를 표시한다.
- **표시**: - 만차 가능성은 주차 가능을 보장하지 않는 참고 정보임을 함께 안내한다.

## 프로덕트 정책

### 1. 주차 데이터 수집·갱신 정책

수집 범위: - 수집 출처는 서울주차정보시스템 홈페이지 화면이다.

- 수집 대상은 '성수동' 검색 결과의 주차장이다.
- 수집 항목은 주차장명, 주소, 주차장 코드, 전체 주차면수, 주차가능면수, 수집 시각이다.
- 서울시 영주차장 정보 공공 API는 실시간 주차면수를 제공하지 않아 수집 출처에서 제외한다.
- 성수동 외 지역은 MVP 수집 범위에서 제외한다.

수집 방식과 AI 활용: - 반복 수집은 고정된 자동화 코드로 수행한다.

- AI는 초기 사이트 구조 분석, 예외 처리, 데이터 이상 탐지에만 활용한다.
- AI가 매 수집마다 데이터를 직접 판단하게 하지 않는다.

갱신 주기와 재시도: Q. 수집 주기를 5~10분 중 몇 분으로 확정할까요?

데이터 정제 규칙: - 수집 데이터는 PKLT_CD 기준으로 중복을 제거한다.

- 전체 주차면수와 주차가능면수는 숫자 형식을 검증한다.
- 검증을 통과하지 못한 값은 사용자 표시용 최신 상태로 반영하지 않는다.

수집 상태 구분: - 주차장별 수집 상태는 정보수집중, 미연계, 수집실패로 구분한다.

- 운영 화면의 수집 현황은 정상, 지연, 오류로 구분해 표시한다.

마지막 정상값 보존: - 마지막 정상 수집값과 그 수집 시각을 저장한다.

- 수집 실패 시 마지막 정상 수집값을 덮어쓰지 않고 유지한다.
- 수집 이력이 없는 주차장은 수집 이력 없음으로 처리한다.

오래된 데이터 처리: Q. '최신 정보 아님'으로 표시할 기준 시간은 얼마로 할까요?

서울주차정보시스템 화면 수집 데이터의 수집 범위, 주기, 정제, 상태 구분, 보존 기준을 정한다.

### 2. 주차 상태 표시 및 면책 안내 정책

혼잡 상태 종류: - 혼잡 상태는 여유, 혼잡, 만차 세 가지이다.

- 상태를 판단할 수 없으면 확인 불가로 표시한다.

상태 판정 기준: Q. 여유·혼잡·만차는 어떤 기준으로 판정할까요?

시각 표시 기준: - 마지막 업데이트 시각은 한국 시간 기준으로 표시한다.

- 상태를 확인할 수 없을 때는 임의의 상태를 표시하지 않는다.

참고 정보 고지: - 상태 정보와 예측 결과는 주차 가능성을 보장하지 않는다는 안내를 표시한다.

- 수집 지연이나 실패 시 최신 상태를 확인할 수 없다는 안내를 함께 표시한다.
- 운전 중 이용을 최소화하고 정차 후 이용 또는 음성 안내를 유도하는 문구를 표시한다.

사용자에게 보이는 혼잡 상태 판정, 시각 표시, 확인 불가 처리, 참고 정보 고지 기준을 정한다.

### 3. 역할별 접근 권한 정책

역할 정의: - 운전자는 주차장 목록, 검색, 상태 확인을 이용하는 서비스 사용자이다.

- 데이터 운영자는 수집 현황과 오류 이력을 점검하는 내부 사용자이다.
- 서비스 관리자는 서비스 전반을 관리하는 내부 사용자이다.

역할별 접근 범위: - 운전자는 주차장 목록, 검색, 상세 상태 화면을 조회할 수 있다.

- 데이터 운영자만 운영 화면의 주차장별 수집 현황과 오류 이력을 조회할 수 있다.
- 운전자에게는 운영 화면 진입점을 노출하지 않는다.

서비스 관리자 권한: Q. 서비스 관리자는 어떤 권한을 갖나요?

운전자, 데이터 운영자, 서비스 관리자의 접근 범위를 정한다.
