# 모두의주차장 구매 전 흐름 개선 — 프로토타입 검토안

> **최신 정정 — 진행률 재산정 중:** 기존 ‘구현 학습 60%/80%’는 철회했다. AI 구현·검사와 팀 학습·합의 완료를 구분한다. 사용자는 영역별 표시(A2)를 선택했다. 전체 50% 계산안은 사용하지 않는다. DB 기본 설계 합의만 기존 4/4 기준 100%이며 프로토타입 최종 검토·UT 준비는 분모/완료 근거 확정 전 산정 대기다. ‘다음 단계’는 먼저 필요한 질문을 제시한다는 뜻이다. [진행도 기준·근거·다음 질문](../review/PROGRESS_REVIEW.md)을 먼저 읽는다. 취소된 상세 여백 수정은 적용하지 않는다.

기준일: 2026-10-22. 사용자 제공 스케치와 로컬 앱 캡처를 확인한 뒤 작성한 제안이다. C1/D1/E1로 모바일 웹·상호작용 예시 지도·동일 가상 상품의 비교 모드를 합의했다. 로컬에서 작은 동작 묶음별로 구현·확인하며 배포는 하지 않는다.

## 3. 합의한 구현 경로

**기존 앱의 구매 전 맥락을 재현한 모바일 웹 프로토타입**을 추천한다. HTML/CSS/JavaScript와 JSON을 역할별 파일로 나누고, 한 번에 완성하는 대신 다음 묶음마다 팀원이 이해·확인한 뒤 이어간다.

1. 사용자 흐름과 화면별 상태·버튼 동작을 함께 확정한다.
2. 유미는 지도/패널·비교 카드·상품 상세의 구조를, 종현은 15개 기본정보·가상 현황·공통 판정 함수를 준비하는 분담안을 검토한다.
3. 한 시설의 목록→선택→상세→목록 복귀를 연결해 공통 양식을 확인한다.
4. 같은 구조로 15개를 연결하고 5단계·시각 없음·오래됨·조회 실패·기록 없음 상태를 적용한다.
5. 고정 테스트 시각·초기화·진행자용 시나리오 제어를 연결한다.
6. 기능 점검 후 사용자 테스트 준비 상태를 확인한다.

07과 08은 별개의 상품 데이터가 아니라 같은 상세 화면의 축약/펼침 상태로 구현하는 안이다. 실제 드래그 제스처를 먼저 만들기보다 버튼·스크롤로 동일한 과업을 수행할 수 있게 하는 방식을 검토한다.

프로토타입 자체는 실제 앱에 코드를 주입하거나 운영 중인 모두의주차장에 연결하는 기능이 아니다. 네이티브 앱의 로그인·결제·구매 후 흐름까지 재구현하는 것은 현재 추천 범위가 아니다. 구매 버튼은 사용자 1안 선택으로 로컬 선택 기록 후 테스트 종료하도록 확정·구현했다.

## 4. 새로 드러난 범위·데이터 차이

### 지도

기존 PRD는 지도 탐색을 후속으로 두었지만, 사용자 최신 설명은 기존 앱의 지도 맥락을 포함한 개선 방향이다. 앱 맥락의 지도 화면과 실제 지도 API·길찾기·현위치 구현을 구분해 선택한다. D1 선택으로 테스트용 상호작용 도식 지도를 사용하기로 합의했다.

- 추천: 예시 성수동 지도를 도식화하고 테스트 표식·목록을 연결한다. 좌표와 도로·거리를 실제 지리 정보처럼 주장하지 않는다. 지도에는 ‘테스트용 예시 지도’를 표시한다.
- 대안: 실제 지도와 검증한 좌표를 사용한다. 공급자 선택·접근 조건·좌표 확보를 먼저 확인해야 한다.
- 축소안: 지도는 참고 배경으로만 두고 목록에서 선택한다. 지도 표식 선택 과업은 검증할 수 없다.

### 가격·거리·상품·운영 조건

현재 받은 15개 목록에는 이름·주소만 있다. 스케치의 기존 상품 가격·거리·시간·차량 제한을 성수동 시설의 실제 조건으로 재사용하지 않는다.

- 추천: 비교 과업용 가상 상품·가격·거리·이용시간을 별도 테스트 데이터로 준비한다. 상태뿐 아니라 이 항목들도 가상임을 구분한다. 운영 상태 DB에 실제 판매 정보처럼 섞어 저장하지 않는다.
- 가상 주차권이 있다는 사실을 실제 모두의주차장 판매 제휴의 증거로 표현하지 않는다. 15개 시설의 실제 판매 연결은 여전히 별도 미확인이다.
- 실제 상품 정보를 사용하려면 시설·상품 연결과 최신 조건을 확인한 뒤 반영한다.

### 비교 UT

비교를 하려면 기존안과 개선안의 목적지·시설·가격·거리·시간·기본 조작을 맞추고 상태·시각 정보의 차이를 중심으로 본다. 기존안은 서울시청 캡처, 개선안은 성수동 인터랙티브 화면처럼 조건이 다른 상태로 결과를 단순 비교하지 않는다.

추천은 같은 모바일 웹 틀과 같은 테스트 데이터에 진행자용 ‘기존안/개선안’ 모드를 두는 방식이다. 기존안은 새 상태·시각 영역을 제외하되, 기존 이용 조건·만차 가능성 안내를 없애지 않는다. 이는 실제 앱 자체의 검증이 아니라 기존 화면 구조를 참고해 만든 비교 모형임을 밝힌다. 개선안부터 만들고 비교 모드는 뒤에 붙이는 순서는 선택할 수 있다.

## 5. 마지막에 확인할 선택

1. C 구현 형태: 구매 전 맥락의 동작 모바일 웹 / Figma 등 클릭 연결 모형 / 실제 모바일 앱 프로젝트 / 기타.
2. 지도 범위: 테스트용 상호작용 도식 지도 / 실제 지도·좌표 / 지도는 참고 배경, 목록만 선택 / 기타.
3. 비교·상품 데이터: 같은 가상 상품 데이터로 기존안·개선안 모드 / 개선안과 가상 상품부터 준비하고 비교 모드는 후속 / 실제 상품 정보를 확인한 뒤 화면 구성 / 기타.

사용자는 C1/D1/E1을 선택했다. 아래 확정사항은 재질문하지 않는다: HTML/CSS/JavaScript 기반 모바일 웹, 상호작용 예시 지도, 동일 가상 상품 데이터로 기존안/개선안 모드. 실제 지리 위치·현황·판매 상품으로 주장하지 않는다.

## 6. 구현 학습 진행도

5개 동작 묶음으로 진행한다: ① 한 시설 목록→상세→복귀 ② 15개·검색·정렬·선택 연동 ③ 5단계·예외·시나리오 전환 ④ 기존안/개선안·초기화·과업 종료 ⑤ 기능 점검·실행 안내·팀 설명.

①②③④는 AI 구현·점검 기록이다. 이를 팀의 구현 학습 80%로 계산한 보고는 철회했다. 15개·검색·가격/거리 정렬·선택 연동을 연결했다. ③④의 상태/예외·비교·로컬 과업 종료도 구현·브라우저 점검했지만 팀 검토와 원본 재현 확인 전이므로 전체 완료로 세지 않는다.

사용자는 최신 요청에서 기존 서비스와 같은 외형·이용 흐름을 원한다고 명시했다. 원본 앱 캡처에 맞춰 검색 카드·목록 시트·상품 상세 축약/펼침·고정 구매 버튼을 1차 수정했다. 스케치를 러프하게 재현하는 것과 기존 앱의 외형을 충실히 재현하는 것을 구분한다. 실제 앱 전체/픽셀 일치 완료는 아니다.

현재 지도는 사용자 승인에 따라 성수동 Kakao 일반 지도 캡처로 교체했다. 시설 표식은 가상 위치이며 실제 시설 좌표로 검증하지 않았다. 일반 주차권 구매 전 흐름이 현재 재현 범위다. 기존 D1 예시 지도 결정을 새 실제 지도 API 사용 승인으로 해석하지 않는다.

검증·실행법·파일 역할·학습 항목은 [prototype/README.md](../../prototype/README.md)에 모았다. 사용자 1안 선택에 따라 구매하기는 로컬 선택 기록 후 테스트 종료로 연결했다. 실제 결제·예약이 아니다. Chrome의 1건은 AI 기능 점검이며 실제 UT 결과가 아니다.

## 7. 실제 자료 조사 허용과 관찰

사용자는 필요하면 면수·상품·가격·거리·시각을 Chrome에서 직접 확인해도 된다고 했다. 이 허용은 실제 자동 수집·DB 운영의 보류를 해제한 것이 아니다. 실제 현장 요금·모두의주차장 판매 가격·목적지별 거리를 구분한다.

첫 시설의 서울시 화면을 확인해 전체 99면·가능 0면·250원/5분을 관찰했다. 원천 갱신 시각은 검색 결과·상세의 확인 범위에서 찾지 못했다. 시설정보 수정일을 상태 갱신 시각으로 사용하지 않는다. 상세 근거: [Chrome 관찰 기록](../../research/source-observations/gangbyeon-2026-10-22.md). 현재 비교용 가상값을 이 관찰값으로 자동 교체하지 않았다.

## 2026-10-22 추가 결정 및 목록 배치 수정

- 사용자는 A1/B1을 선택했다. 성수동 지도 캡처 배경+가상 표식, 일반 주차권 검색→비교→상세→구매 전 흐름으로 재현 범위를 확정했다. 공유면은 이번 범위에서 제외한다. 성수동 배경 교체 자체는 아직 미수행이며 현재 서울시청 임시 배경을 실제 성수 지도라고 주장하지 않는다. 앞선 지도·공유면 질문 대기 문구는 이 결정으로 해소한다.
- 개선안 목록의 같은 행을 ‘혼잡도 배지 → 주차장 이름 → 갱신 시각 → 거리’로 변경했다. 긴 시설명은 한 줄 말줄임하고 원문은 title·상품 상세에 유지한다. 기존안은 새 상태/갱신 시각을 계속 숨긴다.
- 원천 갱신 시각 없음/최근 기록 없음의 짧은 표시 문구는 아직 제안 단계다. ‘시각 미확인’을 추천하며, 상세의 미확인 사유는 유지하는 방향이다. 사용자 선택 전에는 현재 문구를 임의로 교체하지 않는다.

## 목록 문구 확정 및 갱신 시각 위치 비교

- 현재 ①한 시설 연결 ②15개·검색·정렬 ③상태·예외 점검까지 3/5다. ④비교 조건·초기화·과업 종료 기록과 ⑤최종 실행·팀 설명·UT 준비 확인이 남는다. 실제 사용자 UT·실제 모바일 기기·실제 DB/수집은 미실행이다.

## 이전 상세 배치·AI 검사 기록 — 당시 학습 80% 표시는 철회

- 사용자 요청: 7번 상품 상세 화면의 혼잡도 배지를 주차장 이름 바로 왼쪽에 붙여 한 줄로, 갱신 시각은 그 아래 가운데 정렬한다. 축약/펼침의 공통 헤더에 적용했다. 상태 카드의 중복 배지·시각은 제거했다. 기존안에서는 새 정보가 숨겨진다. 목록의 확정 1안 배치는 유지한다.
- 유미·종현님이 같은 화면을 보며 진행 중이라고 사용자가 알려 주었으므로 같은 화면을 본다는 이유로 학습 질문·합의를 생략하지 않는다. 사용자의 최신 정정에 따라 ‘다음 단계’에는 필요한 질문을 먼저 제시한다. 팀원이 무엇을 실제로 검토·학습했는지는 추정하지 않는다.
- 네 번째 묶음의 같은 비교 데이터, 초기화, 로컬 종료·재시작·기록 유지 검사를 마쳤다. 중복 종료 저장을 막고 저장 성공 후 구매 버튼을 비활성화했다. 시험 구매는 localhost의 별도 저장 영역에서 진행했다.
- 상세 검증과 팀 확인 순서는 [비교·초기화 학습 자료](../../prototype/COMPARE_REVIEW.md)를 따른다. 실제 사용자 UT 성과가 아니다. 다음 ⑤ 화면 크기별 표시·빠른 연속 조작·실행 안내·UT 진행 자료 점검이 남는다.
