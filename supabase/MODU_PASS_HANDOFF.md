## 동작·범위

- Cron → 전용 함수(동시 요청 최대2) → 공개 HTML → 날짜별 상품 → DB → 기존 조회 API → 프로토타입.
- 임의 URL·시설 목록·SQL·과거 날짜 입력을 받지 않는다. 오늘 KST만 수집한다. 자정이 조회 중 지나면 저장하지 않는다.
- 가격, 이름, 상품ID, 판매상태(판매가능/판매예정/판매불가/매진 등), 이용 표시, 판매예정시각, 재고를 구분한다. 원천의 시간대 없는 판매예정시각은 한국 서비스의 UI 기준에 맞춰 +09:00으로 명시 변환한다.
- 제공처 갱신 시각을 알 수 없으므로 우리 수집 시각을 ‘원천 갱신 시각’으로 표현하지 않는다.
- 실패·파싱 변경·타시설·HTTP429는 마지막 성공값을 덮어쓰지 않는다. 화면은 실패 정보와 마지막 상품을 표시하고 구매 테스트를 막는다. 미확인 상태를 판매가능으로 바꾸지 않는다.
- 날짜가 다른 상품을 오늘/미래에 임의 판매하지 않는다. 미래 날짜 조회는 아직 수집 범위 밖이다.
- 상품 조건 상세는 이번 수집에서 새로 긁지 않았다. 기존 검증 조건이 없는 상품은 조건 미확인으로 안내한다. 로그인·구매·결제·차량정보·회원정보는 수집하지 않는다.
- 지도 가격은 합의한 현장1시간 기본요율을 유지한다. 상품 가격 수집이 지도 가격을 상품 최저가로 바꾸지 않는다.
- 5분은 우리 확인 간격이다. 제공처 가격이 5분마다 변경된다는 보장이나 지속 운영 SLA가 아니다.
- 최초 실제 예약 검증과 장기 안정성/실제 사용자 UT는 구분한다.

## 기록 보관

7일 초과 수집 로그·변경 이력 정리 함수와 예약 SQL을 준비했다. 현재 시설 매핑과 현재 상품 행은 역사 로그와 분리한다. **자동 정리 예약은 실행 직전 확인 답변 대기이며 아직 활성화하지 않았다.**

- 수집 예약 활성화: `operations/enable_modu_pass_schedule.sql`
- 정리 예약: `operations/enable_modu_pass_retention.sql`
- 중지: `operations/pause_modu_pass_schedule.sql` (삭제 대신 비활성화)
- 재조회: `checks/modu_pass_readback.sql`

공개 크롤러 안내(`https://app.modu.kr/robots.txt`)는 공개 경로 Allow /, 내이용권·구매 경로 Disallow로 확인했다. 허용 안내가 장기 제공 계약을 의미하지 않는다. 인증 우회·차단 우회는 하지 않으며 구조나 제한이 달라지면 실패 상태로 남긴다.
