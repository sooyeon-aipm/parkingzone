## Summary

공공 API의 성수동 대상 시설 부족에 따라 서울시 주차정보 화면 수집 설계로 전환했다. 주차장·상태 이력·수집 시도 테이블과 시각·검증·보관 정책을 합의하고 화면용 공통 모델로 연결했다. 기존 앱 캡처와 개선 스케치를 참고하여 가상 데이터로 탐색→상세→구매 테스트 종료를 구현했다.

## Implementation

- 테이블: 기본정보 5·상태 8·수집 로그 9컬럼. UUID 키와 FK, 재시도·상태 생성 시도 연결.
- 원천 시각 NULL/UTC·KST 구분, 5단계 반올림 점유율, 20분 초과 지연(임시값), 실패 시 마지막 기록 표시.
- 상태 collected_at·로그 started_at 기준 7일 보관, 조회 제외·매시간 삭제 설계. 실제 DB 작업 미구현.
- 15개 가상 시설, 지도 배경·가상 표식·거리·상품, 검색·정렬·상세 펼침·기존안/개선안·초기화.
- 구매 선택 localStorage 저장·중복 종료 방지. 실행/저장 시 7일 초과 선택 정리. 예약·결제 없음.
- 참여자 보기: participant=1&case=1/2/3. 진행자 도구를 숨기고 정상/지연/시각 없음 시나리오 유지.
- 목록·상세 배치는 사용자가 선택한 안 반영. 취소된 상세 여백 수정은 미적용.
- 실제 화면 관찰과 고정 더미 데이터를 분리했다. 실제 시설 식별자·원천 갱신 시각 확보는 미확인 항목으로 남긴다.
