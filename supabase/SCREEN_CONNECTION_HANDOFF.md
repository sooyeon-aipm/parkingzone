# 실제 DB → 프로토타입 화면 인수인계

기준: 2026-10-23. **등록된 4곳의 조회·목록·상세·실패/복구 연결 완료**.
전체 15곳 수집·팀 학습·수연 승인·실사용자 UT 완료를 의미하지 않는다.

## 팀원이 실행하는 방법

```sh
python3 scripts/serve_prototype.py
```

- 실제 DB: http://127.0.0.1:8765/?data=live
- 더미 연습: http://127.0.0.1:8765/?data=demo
- 기존 정적 서버가 8765를 사용하면 먼저 그 서버를 종료한다. 새 서버는 표준 라이브러리만 사용하며 127.0.0.1에서만 실행한다.
- ‘현황 새로고침’은 이미 수집된 DB 현황을 읽는다. 서울시를 즉시 재수집하지 않는다. 수집은 Supabase의 별도 5분 예약이다.

## 함께 이해할 세 가지

1. **데이터 흐름**: 화면 `/api/parking` → Python 로컬 서버 → `parking-status` Edge Function → `parking_read_snapshot()` → DB. 브라우저에 서버 비밀 키를 넣지 않는다.
2. **시각 구분**: 원천 갱신 시각은 제공처의 상태 시점, 수집 시각은 우리가 받은 시점, 조회 시각은 DB를 읽은 시점이다. 새로고침했다고 제공처의 시각까지 새것이 되지 않는다.
3. **실패 처리**: 새 조회 실패 때 이전 정상 기록을 계속 ‘현재 여유’로 보이면 오해를 부른다. 마지막 기록과 확인 필요로 전환한다. 더미로 몰래 대체하지 않는다.

유미·종현은 같은 시설을 목록에서 고른 뒤 상세의 원천 시각과 면수를 DB 조회 결과와 대조해 보면 된다. 이 문서의 설명·AI 검사가 팀 이해 확인을 대신하지 않는다.

## 파일과 계약

| 파일 | 역할 |
| --- | --- |
| migrations/202610230002_parking_snapshot.sql | 실제 DB에 적용한 서버 전용 읽기 함수. 기존 22개 컬럼 유지 |
| functions/parking-status/index.ts | 고정 조회만 수행. JWT 게이트웨이 검증 ON. SQL 오류·원본 오류·서버 키 미노출 |
| ../config/parking-public.json | 공개 anon 키·고정 조회 URL. secret/service_role 키 금지 |
| ../scripts/serve_prototype.py | 같은 출처의 읽기 전용 프록시. 공개 anon 역할과 조회 목적지를 검사 |
| ../prototype/live-data.js | 실제 시설 UUID와 가상 상품만 연결. 가상 주차 상태는 붙이지 않음 |
| ../prototype/model.js | 5단계 혼잡도, 20분 지연, 7일 만료, 수집·조회 실패 공통 판정 |
| checks/parking_snapshot_contract.sql | 실제 DB 응답 범위·7일 제한·RPC 직접 접근 차단 확인 |

반환 양식은 `data_origin=LIVE`, DB의 `as_of`, `lots[]`다. 각 시설은 id·이름·주소·최근 유효 observation·최신 수집 결과만 포함한다. 관측값은 총면·가능면·원천 시각·수집 시각·품질을 포함한다. 오류 원본·오류 상세·인증값은 반환하지 않는다.

공개 주차 정보 조회용 Edge 경로만 추가했다. DB 테이블의 RLS·익명/일반 사용자 정책은 열지 않았고, 새 RPC 실행 권한도 기존 서버 역할에만 부여했다. 공개 anon 키는 사용자 인증이나 비밀 키가 아니다. 공개 조회 결과를 열람할 수 있어도 DB 직접 조회·쓰기·수집 실행 권한을 받지 않는다.

## 표시 기준

- 실제 모드: 현재 등록된 강변·성수2가1동·서울숲아이티밸리·갤러리아포레 더몰 상가 4곳. 주차 현황만 실제값이고 상품·가격·거리·지도 표식은 가상이다.
- 더미 모드: 15곳·고정 기준 시각·시나리오 선택 유지. 실데이터 모드에서는 강제 시나리오 주입을 잠근다.
- `SOURCE_UNAVAILABLE`, `IN_PROGRESS`, 수집 실패, 화면 읽기 실패, 시각 없음, 20분 지연은 현재 배지를 숨긴다. 최근 7일의 유효 이력만 마지막 기록으로 표시할 수 있다.
- `READ_ERROR`는 화면의 임시 판정이며 DB 결과 코드로 추가하지 않았다.
- 화면을 열어 둔 동안 30초마다 경과 시간만 재판정하고, 화면 복귀 시에도 재판정한다. 원격 재조회는 첫 로드·모드 재진입·새로고침 버튼에서 수행한다.
- 테스트 선택에 `data_origin`을 기록한다. 실제값 모드의 테스트 선택도 실제 예약·결제나 UT 성과가 아니다.

## 실제 확인한 근거

- DB 읽기 함수 적용 후 4곳 응답과 anon/authenticated의 RPC 실행 권한 false를 확인했다.
- Deno 조회 함수 검사 3개, Node 연결·표시 검사 3개, Python 프록시 검사 3개 PASS.
- 실제 DB 조회 계약 검사 6개 모두 true. 현재 응답·권한 검사이며 모든 미래 상황의 운영 보장은 아니다.
- 인증 헤더 없는 Edge 요청은 `UNAUTHORIZED_NO_AUTH_HEADER`로 거절됐다. 로컬 프록시의 공개 anon 키를 통한 요청은 실제 화면에 도달했다.
- Chrome에서 성수2가1동의 가능 141/총 161, 원천 00:39, 수집 00:40을 DB와 대조했다. 관찰 시점 값이며 현재 주차 상태가 아니다.
- 강변은 실제 SOURCE_UNAVAILABLE이므로 확인 필요와 마지막 기록을 표시했다.
- 로컬 조회 설정 파일을 잠시 이동해 **의도적으로** 조회 실패를 만들었다. 모든 현재 배지를 숨기고, 상세에 마지막 조회 기록을 표시했다. 파일 복원 후 새로고침으로 정상 복구했다. 실제 서울시/DB 장애를 관찰했다는 뜻은 아니다.
- 더미 15곳·갱신 지연 연습·실제 모드 재전환을 확인했다. 구매하기는 테스트 종료로 이어졌고 브라우저 테스트 선택 1건이 추가됐다. 실제 사용자 UT로 세지 않는다.
- 데스크톱 Chrome의 모바일 프레임 검사다. 실제 모바일 기기 검사는 별도다.

## 남은 일

원래 목록의 나머지 11곳은 원천 코드·주소를 대조하고 등록해야 한다. 실제 상품·가격·거리·지도 좌표, 실제 모바일 기기, 팀 재현·수연 검토·사용자 UT는 아직 완료하지 않았다. 매시간 만료 정리의 첫 정각 실행은 수집 인수인계에서 별도로 추적한다. 이 작업에서는 커밋·푸시·Notion 갱신을 하지 않았다.
