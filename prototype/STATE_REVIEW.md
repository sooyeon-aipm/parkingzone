# 세 번째 학습 묶음 — 혼잡도와 정보의 신뢰도를 구분하기

> 이 문서는 AI가 작성한 설명·과거 검사 기록이다. 팀 학습·검토 완료나 단계 진척의 증거로 자동 계산하지 않는다. 진행도·다음 질문은 [진행도 재검토](../docs/review/PROGRESS_REVIEW.md)를 따른다.

상태 5단계는 주차장이 얼마나 차 있는지, 예외 표시는 그 수치를 지금 믿고 써도 되는지를 나타낸다. 수집 실패를 만차 또는 여유로 바꾸지 않는다.

| 진행자 선택 | 목록 표시 | 상세에서 확인할 것 |
| --- | --- | --- |
| 정상 | 여유·보통·혼잡·매우혼잡·만차, 갱신 11:55 | 강변 예시 80/100면, 현재 상태 |
| 갱신 지연 | 확인 필요, 갱신 11:30 | 마지막 기록 80/100면, 최신 정보 아님 |
| 원천 갱신 시각 없음 | 확인 필요, 미확인 | 마지막 기록은 있으나 기준 시각 미확인 |
| 최신 조회 실패 | 확인 필요, 갱신 11:55 | 마지막 기록 유지, 조회 실패 안내 |
| 최근 기록 없음 | 확인 필요, 기록 없음 | 면수 생략, 최근 유효한 수집 기록 없음 |

표의 면수·시각은 고정 가상 데이터다. 원천 시각 없이 면수만 아는 것은 현재 상태를 안다는 뜻이 아니다. 기록 자체가 없으면 ‘마지막 기록’이라는 제목도 쓰지 않고 ‘주차 정보’로 표시한다.

## 팀원 확인 순서

1. 유미: 같은 주차장을 선택하고 진행자 시나리오를 바꾸며, 예외에서도 현재 혼잡도처럼 오해할 만한 배지가 남는지 확인한다.
2. 종현: `scenarioLot()`에서 만드는 가상 예외와 `model.js`의 판단 결과를 연결해서 읽는다. UI에서 ‘기록 없음’과 ‘시각 미확인’이 다른 이유를 설명해 본다.
3. 두 사람: 갱신이 20분을 넘으면 현재 배지를 숨긴다는 정책이 실제 사용자가 이해하기 쉬운지 의견을 기록한다. 20분은 합의된 프로토타입 임시 기준이며 제공처의 실제 갱신 주기로 검증된 값은 아니다.

위 담당은 학습 제안이며 실제 WBS 배정이나 팀원 수행 완료가 아니다.

## 확인 근거

2026-10-22, 로컬 Node 공통 판정 검사: 혼잡도 경계 9건, 갱신 20분/20분1초 2건, 원천 시각 없음·조회 실패·기록 없음·7일 초과·잘못된 면수·미래 시각 6건, 총 17건 통과. 15개 더미 시설의 5단계 분포와 한국 시각 표시도 확인했다.

Chrome 모바일 프레임에서 원본 캡처 배경 교체, 확정 1안·비교 버튼 제거, 정상 5단계, 상세에서 지연·시각 없음·실패·기록 없음 표시를 확인했다. 실제 모바일 기기·실사용자 UT·실제 DB/수집 검증은 아니다.

다음 네 번째 묶음은 기존안/개선안 비교 조건, 초기화, 테스트 종료 기록을 팀 관점에서 함께 확인하는 것이다. 기능 대부분이 이미 연결되어 있더라도 실제 UT 완료나 개선 효과로 보고하지 않는다.
