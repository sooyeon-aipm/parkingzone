# 네 번째 학습 묶음 — 공정하게 비교하고 다시 시작하기

> 이 문서는 AI가 작성한 설명·과거 검사 기록이다. 팀 학습·검토 완료나 단계 진척의 증거로 자동 계산하지 않는다. 진행도·다음 질문은 [진행도 재검토](../docs/review/PROGRESS_REVIEW.md)를 따른다.

기존안과 개선안에서 다른 주차장·가격·거리를 보여주면 선택 차이가 혼잡도 때문인지 판단하기 어렵다. 같은 조건에서 새 상태·시각 정보의 차이를 비교한다.

## 확인한 비교 조건

- 같은 15개 시설, 같은 주소·가상 상품·가격·거리·이용시간, 같은 정렬·검색 기준을 쓴다.
- Chrome에서 기존안/개선안의 시설명·거리·상품/가격 텍스트 15개가 일치함을 확인했다.
- 기존안은 새 혼잡도 배지·갱신 시각·상태 카드를 숨기고 기존 만차 가능성 안내는 유지한다. 기본 주의사항 텍스트도 동일함을 확인했다.
- 개선안 상세는 혼잡도와 이름이 한 줄이며, 갱신 시각은 아래 중앙에 있다. 축약/펼침 모두 같은 헤더를 사용한다. 카드의 중복 배지·시각은 제거했다.

## 초기화와 테스트 종료

‘처음으로’는 검색, 날짜·예정 시간, 거리순 정렬, 정상 시나리오, 지도 확대, 주차권 표시, 선택·상세를 초기화하고 기존안으로 돌아간다. 기존 선택 기록을 지우는 기능은 아니다.

실제 브라우저에서 검색어·10월23일·시간 조건·가격순·조회 실패·상세 펼침 등을 변경한 후 초기화를 확인했다. 예정 시간을 3시간으로 설정한 뒤 1시간으로 초기화하는 동작도 따로 확인했다.

구매하기는 선택 시설·상품·모드·시나리오·날짜·시간·실제 기록 시각·고정 데이터 기준 시각을 로컬에 저장하고 종료한다. 실제 결제와 연결하지 않는다. 저장 성공 후 완료 상태를 기억하고 구매 버튼을 비활성화해 같은 종료 선택의 중복 저장을 막는다. 다시 테스트하기로 새 시도를 시작하면 다시 구매 버튼을 사용할 수 있다. 저장 실패 시 성공 화면을 표시하지 않는 코드를 유지했다. 저장 실패를 브라우저에서 강제로 재현하지는 않았다.

## 이번 검증의 저장 영역

팀이 사용 중인 http://127.0.0.1:8765 와 기능 점검용 http://localhost:8765 는 같은 서버 화면을 읽지만 브라우저 저장 영역이 다르다. 이번 구매 종료 검사는 localhost에서 진행했다.

localhost의 저장 건수 0→1, 다시 테스트하기 후 1 유지, 새로고침 후 1 유지를 화면에서 확인했다. 이 1건은 AI의 기능 점검 기록이며 실제 사용자 UT 결과가 아니다. 127.0.0.1의 사용자 기록을 테스트용으로 삭제하거나 추가하지 않았다.

연속 조작 점검 중 목록 진입이 확인되지 않은 1회가 있어 상태를 확인한 뒤 단계별로 재실행했다. 재실행은 통과했고 원인은 확정하지 않았다. 빠른 연속 조작·화면 크기별 최종 점검에 이 항목을 포함한다.

## 유미·종현님이 같은 화면으로 볼 것

1. 같은 시설의 기존안·개선안을 전환하며 무엇이 달라지는지 확인한다. 가격/거리/주의사항 변화로 결과가 달라지지 않게 한다.
2. 검색·날짜·시간을 바꿨다가 처음으로 돌아오고, 화면 초기화와 기록 삭제가 다른 동작임을 확인한다.
3. 기록에는 ‘어떤 시설을 골랐는지’가 남지만 ‘왜 골랐는지·시각을 이해했는지’는 남지 않는다는 점을 확인한다. 이유·이해 여부·망설인 지점은 UT 관찰표에서 별도로 기록한다.

이는 함께 볼 학습 항목이며 팀원 학습/실제 UT 완료를 뜻하지 않는다. 다음 다섯 번째 묶음은 화면 크기별 표시, 빠른 연속 조작, 실행 안내 및 UT 진행·관찰 자료를 확인하는 것이다.
